# Examples

## Too much: the Dual governance page

A 300-word page with a headline, three bullet cards, four capability cards, a three-node diagram, an addition table and a footnote. Every section is readable, but the reader has to assemble the point, and the next reply regressed because the shape lived in the conversation, not in a rule.

## The same idea, one screen

**Maya can <span class="token">Edit</span> <span class="token">Lead intake</span>.**

That sentence is a Grant: one row in one table.

```
Group "Sales team" ──View + Use──▶ Space "Sales" ──limit: View──▶ Workflow "Lead intake"
                                              Maya's total: View, Use, Edit
```

| Capability | Means                       |
| ---------- | --------------------------- |
| View       | See it                      |
| Use        | Run it in your own work     |
| Edit       | Change and publish it       |
| Manage     | Share it, place it, archive |

No deny rules. Removing access means removing a Grant.

About 60 words, one diagram, one table. The reader gets the rule in five seconds.

## A chat reply

Bad: twelve bullets, a status update, and the PR body restated.

Good: one line ("Scope keeps the chosen app in the URL."), a four-row before/after table, one ask ("Merge?").

## A decision

Bad: three paragraphs describing the options.

Good: two drawn screens side by side, each with its cost, the recommended one marked, and one line of why.
