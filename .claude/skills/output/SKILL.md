# Output

The user reads the result once, on a phone or a desktop, and never the process.

- **The visual is the reply.** Anything with structure (a plan, a comparison, a flow, numbers, a set of choices) is one page rendered in the thread; a one-line answer to a one-line question stays a line. If the reply still makes sense with the page removed, it is prose with a picture: rebuild it.
- **Relationship first.** Ask what differs between the things shown (position, size, order, containment, connection, before and after) and let that choose the form. There is no catalogue of charts or templates: the content decides, and a page may look unlike the last one.
- **Each fact once.** Words outside the page carry only what it cannot: a link, a caveat, the decision the user owes. Nothing on the page is said again beside it.
- **Answerable.** A choice the user owes has a short id and shows the option you would take, so one word answers it.
- **Both widths.** The page is fluid: it reads at 360px and fills 728px. Check both before showing it. Nothing needed lives only in a hover, since a phone has none.
- **The host's look.** Its theme tokens, font, radius and neutrals; a hue only for a category, state or value its legend names. Real content and one worked example; no gradients, shadows, glow or animation.
- **Short.** One screen, two for a plan. Cut what describes the process or already lives in the PR.

Where a page cannot render, such as a PR body, use a Mermaid diagram or a compact table, never paragraphs.
