# Scope intent

- One page lists operations grouped by app, one 32px heading per app carrying its mark and name. Any app with a failure leads, then the busiest; inside a group failing operations lead, then the busiest. Each row leads with the side glyph, then the operation name; errors, runs and typical duration share fixed right columns, so every row lines up. No group collapses and no heading counts. The same operation name from two sides is two rows. An operation is a root span's name; HTTP operations use method and route or path, with unmatched requests grouped rather than one row per scanner path. Scope keeps each service's newest ordered release, but never deletes an unversioned or unordered service for it.
- Every pane starts with one 32px heading band, so row dividers line up across panes: operations with its first app heading, traces with the selected operation's name and app mark, the waterfall with the selected trace's short id and age. With nothing selected the band stays empty. The chosen operation lists its slowest traces with its newest failures among them. Rows show age, a short trace ID, failure status and duration. Hover names the failing span; selecting the trace opens that span's diagnostic, not a repeated message on the row. Only top-level traces are rows. New arrivals appear directly, without animating row height or rescanning every trace merely to animate it. One stale mark in the bar carries the oldest age among the operations and trace readers, and its retry refreshes both; no pane repeats it.
- Spans share their trace's time scale and are 48px rows whose dividers run pane edge to edge. The waterfall is always fully expanded; nesting is indentation only. A span's bar takes the hue of the app that ran it, and a failed span is destructive; a span that crosses into another app leads with that app's mark. The first failure starts picked. Only a span with additional information opens the inspector: its error, attributes and logs follow the spans as full-bleed rows, without repeating its row or attributes such as `code.function` that only repeat its name. The error sits under an `error` key in the same muted key column as the attributes, its message in destructive text. Selection stores operation, trace and span identities in the URL, never copies of live records. Back keeps the selection and moves up one level.
- GitHub Actions is the CI side: each repository is a section with GitHub's mark, each workflow an operation, a run's trace its jobs and steps; a failed run's status names the step that failed, whose details link to its log.
- On a phone every list runs edge to edge in 48px rows with every operation column, and the trace detail pushes full-screen. The bar shows the app's mark and name at the root, and Back plus the pane's title when pushed. A phone starts with no operation selected; a desktop layout defaults to the first. Focus follows Tab, never the selected row.
- Each pane selects with one click; there is no palette, search field or page-wide key handling.
- Scope's waterfall keeps its own time-scale geometry and composes `Trace` only where a tree is the data shape.
