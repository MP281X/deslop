# Scope intent

- One live page, no panes: each app that started traces is a section with its mark, name and newest release in muted figures, its server, web and iOS operations together under it with no dividers or sub-headers, apps with failures first. Server and web ship together and an iOS app on its own, so hovering the release names each side's; no icons or second version in the heading. Scope keeps only each service's newest release (OTel's `service.version`), deleting what older ones sent, so a fixed bug's traces don't linger; a service with no version, or one Scope can't order (anything but dot-separated numbers), is never deleted for it. Its rows are operations (a root span's name; an HTTP span reads as its method and route or, for a client, path, such as `POST /api/apps`; server requests no route matched share `GET (no route)`, so scanners don't make a row per path), each led by the icon of the device it starts on, as Auth marks a sign-in (server, browser, phone), in that side's hue from DESIGN.md: the failure count as a red badge with no word, runs, and one duration, the typical one; failures first, then the busiest. The same name from two sides is two rows. The page updates as traces arrive, without a refresh button.
- An operation opens on its slowest traces, slowest first, its newest failures always among them, one line each: age, then at the right a red badge naming the span where it broke, like the operation's failure count, and the duration; no bar and no error text. The error shows first in the span that broke, once opened. Only top-level traces are rows; their spans never are.
- A trace opens under its row on its spans, each on the trace's own time scale with no axis labels, each bar in the hue of the side it ran on, so a page's spans and its server's read apart at a glance; the first failure starts picked. Where a trace enters another app, its span leads with that app's mark; no words or device icons there, since the bar's hue already tells the side. Only a span with something more to show opens; a picked one shows its attributes and logs, not its name or duration again, or an attribute that only repeats its name (such as code.function).
- GitHub Actions is the CI side: each repository is a section with GitHub's mark, each workflow an operation, a run's trace its jobs and steps; a failed run's badge names the step that failed, whose details link to its log.
- Durations stay on one line in their column: `412 ms`, `2.8 s`, `28 s`, `48 min`, `1.2 h`.
- On a phone an operation keeps its name, failures and typical duration; runs show from wider screens.
- Chevrons sit at the right and the whole row opens, as in Deploy. The bar's field narrows apps and operations; no filter chips or commands.
