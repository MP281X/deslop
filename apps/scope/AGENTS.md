# Scope intent

- One live page groups operations by app, with server, web and iOS operations together; failures first, then the busiest. The same operation name from two sides is two rows. An operation is a root span's name; HTTP operations use method and route or path, with unmatched requests grouped rather than one row per scanner path. Rows show failures, runs and typical duration; release versions stay out of headings. Scope keeps each service's newest ordered release, but never deletes an unversioned or unordered service for it.
- The chosen operation lists its slowest traces with its newest failures among them. Rows show age, a short trace ID, failure status and duration. Hover names the failing span; selecting the trace opens that span's diagnostic, not a repeated message on the row. Only top-level traces are rows. New arrivals appear directly, without animating row height or rescanning every trace merely to animate it.
- Spans share their trace's time scale. Bar hue identifies where each ran; a cross-app span leads with that app's mark. The first failure starts picked. Only a span with additional information opens the inspector: its error, attributes and logs, without repeating its row or attributes such as `code.function` that only repeat its name. Selection stores operation, trace and span identities in the URL, never copies of live records. Back keeps the selection and moves up one level. The trace pane has no header: its age and ID already sit on the selected row, and there is no copy button.
- GitHub Actions is the CI side: each repository is a section with GitHub's mark, each workflow an operation, a run's trace its jobs and steps; a failed run's status names the step that failed, whose details link to its log.
- On a phone an operation keeps its name, failures and typical duration; runs show from wider screens. The bar keeps its leading slot's width on every pane and names the pane, so the title and the search control never move.
- The bar's palette opens with ⌘K or the search control and lists the chosen operation's traces, every operation and the other Deslop tools; typing filters them. Searching is how the page moves; there are no filter chips.
- Scope's waterfall keeps its own time-scale geometry and composes `Trace` only where a tree is the data shape.
