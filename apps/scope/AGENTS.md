# Scope intent

- **Operations.** One list for the chosen app, without groups or headings. Each row leads with the operation name; failures, runs and typical duration have fixed right columns. Hide the failure column when none failed. Failures lead, then most recently seen. Only duplicate names from different sides gain a muted 12px side glyph. An operation is a root span's name; HTTP uses method and route or path, grouping unmatched requests rather than scanner paths. Keep each service's newest ordered release without deleting unversioned or unordered services.
- **Apps.** The bar has one mark-only tab per app, accessibly named. Always choose one; a missing or obsolete URL choice redirects, replacing history, to the app with the newest failed trace, else the first tab. Changing apps clears operation, trace and span selections outside it; choosing the current app does nothing.
- **Frame.** Bar tabs: 10m, 1h, 24h, 3d, default 1h, stored in the URL. Filter by root start; remove operations without in-frame traces but keep every app with retained traces. Failures, runs, duration and rows count only in-frame traces. A frame change keeps a trace still inside it, clears one outside, and falls back when the operation has no trace left. Empty reads `No traces in this frame`.
- **Headings.** Each pane starts with an `ItemListHeading`: traces with the operation's app mark and name; the trace pane with a muted trace glyph, short id and age. An unselected pane keeps its heading icon, otherwise empty.
- **Traces.** Show the operation's slowest traces and newest failures. Each top-level trace row has age, short ID, failure dot immediately after it and duration. Hover names the failing span; selecting opens its diagnostic, not a repeated row message. New arrivals appear directly without rescanning every trace. Operations and traces are independent readers.
- **Flame.** A pinned 24px axis marks 0, quarters and total in tabular figures: first label left-aligned, last right-aligned, others centred on ticks. Lanes fill the width without horizontal scrolling: root first, each job (root's direct child) next with after-label space reserved, deeper spans in the first free lane without overlap. Bars are 22px tall, separated by 2px, with a 1px background seam at the right edge except on 2px ticks. Position and size by trace time; app hue normally, destructive on failure. Denied sign-ins keep app hue and a `denied` detail key with a lock in normal text. OTLP links in either direction join traces into one flame; linked roots sit under the linking span.
- **Labels.** Root and job names and durations fit inside their bar, else after it while the free lane space permits, else hide. Deeper spans show names only in detail. Every span's parent job, name and duration remain its title and accessible name. Spans shorter than 2px are 2px ticks; tap targets are at least 12px wide.
- **Selection.** Click or Enter picks a bar with a 1px foreground outline inside. Below a hairline, show app mark, name (destructive on failure), `<app> · at <offset>` and right-aligned duration, then error, attributes and logs without dividers. Omit attributes such as `code.function` that repeat the name. The muted key column holds `error`; error messages and failing log messages are destructive. Left/Right choose siblings, Up/Down parent or first child. Pick the first failure initially. The URL stores operation, trace and span identities, never record copies. Back keeps selection and app filter while moving up a level.
- **CI.** GitHub Actions is the CI side: repository sections with GitHub's mark, workflows as operations, runs as traces of jobs and steps. Name runs by build number plus attempt after a dot when not first. A failed run names the failing step. With `GITHUB_TOKEN` access, attach logs to the step or job whose time holds them; detail links to GitHub's log.
- **Phone.** Keep every operation column and push trace detail full-screen. The root bar shows Scope's mark, scrolling app marks, frame and account without wrapping. A pushed pane shows Back and its title, hiding the frame. Phones start without an operation selected; desktop defaults to the filtered list's first operation. Focus follows Tab, never selection.
- **Navigation.** Each pane selects with one click; no page-wide key handling.
