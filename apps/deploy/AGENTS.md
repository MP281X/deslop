# Deploy intent

- **Machines.** The bar's section control shows each machine's icon and name in its colour: dev spring blue, desktop autumn yellow. An unreachable machine has a hollow dot beside its name, no status text or pane popover. Hide the control for one machine. On phones show machine marks only, with accessible names, beside the brand icon, ranges and account.
- **Panes.** Wide screens put the apps in a resizable ~340px list beside the chosen app's processes under the machine's charts. Phones show charts above the list and push processes full-screen with Back and the app's name; machine and range controls stay on the list. The URL holds machine, app, phone pane and range. No machine filter or Monitor page; `/monitor` redirects here.
- **Apps.** Start with an `ItemListHeading` “Processes” and stack icon, aligned with the charts' 32px title band. Failures and warnings lead, then high-impact apps by memory, then “Low impact” with a gauge icon, then scheduled jobs with a clock icon. Headings follow the preceding divider without a gap. The low-impact group uses the charts' peak thresholds for the chosen range; failing or warning apps stay above it. Hide the heading when either app group is empty. Apps have no end action; ports end at the gutter. A failed service shows why it stopped and how long ago, not its description. Centre icon and dot boxes on one row axis; error detail shares the dot's destructive colour.
- **Ports.** Each is an `outline` chip, digits ending on one edge, never cut: exposed ports open their endpoint in foreground text, exposable ports open Expose in muted text, others are muted and inert. Keep all three distinct on a selected row's stock muted background. Agents hide exposures through `hide_exposure`.
- **Jobs.** Show the next timer start, or a failure dot and age, then a 20px play button with a 12px glyph to run now. While running, count elapsed time in the time column and keep play disabled in place. Jobs have no chart band.
- **Charts.** Memory, CPU and Disk are three equal charts across on wide screens, with names and current figures in a 32px title band and bottom divider. Phones stack 64px charts with the same title band, figures right-aligned and one time axis below the last. Memory and CPU stack machine bands on 0–100%; Disk is one used-space band. Time labels are HTML, not non-uniformly scaled SVG text. Hover shows a stock tooltip with band name, time, value and a vertical cursor. Choosing an app focuses its Memory and CPU band, or its low-impact block, fading others without adding a band. No Memory|CPU tabs, metric in the URL, per-core, network or disk I/O charts, or per-app % or MB figures.
- **Bands.** Every app recorded in the range keeps its band, stopped ones too, named by unit when its row is gone. App memory and CPU come from cgroups, including processes between samples; work in `app-<name>.slice`, such as T3 agents, counts as that service. Shrink app memory to fit machine used memory. Low-impact apps and the rest of the machine use two darker greys.
- **Range.** One bar control for all machines: 1m, 10m, 1h, 24h, 7d. Keep the opened range in view and axes clock-aligned. Unrecorded time and samples missing a reading stay blank.
- **Samples.** Sample every second; save every 30 seconds and on shutdown. Retain seconds for one minute, 10-second samples for ten minutes, minutes for one hour, quarter-hours for one day and hours for one week. Merged samples and chart points average their bucket. Record each core, memory and CPU of every service and container holding at least 1 MiB, and used disk summed over mounts. Disk history has no migration or backfill. Browser, worker and MCP responses return at most 60 points per range, with mounts and load once.
- **Expose.** The dialog title is the app's mark, name and port chip. Ask only who reaches it: full-width Tailnet and Public tabs over the fixed tailnet URL or a typed public hostname; Cancel and Expose in the footer.
- **Processes.** Show the whole tree without row dividers, heaviest first, with command label and fixed, right-aligned MiB and CPU % columns; missing CPU is a muted dash. Label the program or app in foreground and its detail muted; truncate detail before name. Fold a child matching its parent's label into it, counting both memory and CPU there. Otherwise never group processes; those below 2% of app memory and 0.5% CPU read muted. The full masked command is the hover tooltip; use raw `/proc` comm only without arguments, such as a zombie. A shell shows its script's command past setup (`source`, `shopt`); an interactive shell shows its working directory. Omit values of non-subject flags; mask secret-looking flags, variables, long opaque strings and URL credentials on the worker. PID and PPID stay internal; never read environment. Omit nameless listeners and ordinary system-service noise. Marks share one optical size: canonical Deslop glyphs and SVGL registry software marks.
- **Recovery.** The bar's `Problem` sits before the range. A sleeping worker must not delay another worker's refresh, local monitoring or the shell. Show cached history immediately; refresh workers with bounded deadlines and explicit offline states. Inventory and history load and recover independently; neither replaces the other's usable content. An authorized empty history is empty, not loading.
