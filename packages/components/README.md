# @deslop/components

Import the same API from `@deslop/components/web` or `@deslop/components/native`; only the elements you draw in the slots differ. Shared types come from `@deslop/components/model`.

- `Row(h, {item, active, muted?, cover?, trailing?, select?})`: `item` is `RowData`; `cover` and `trailing` are host elements. If no trailing element is supplied, the row draws `item.trailing` as tabular figures. `select` is the same headless part as `Selection.select`; omit it for a non-interactive row.
- `ListDetail(h, {selection, defaultId?, loading?, header?, empty?, list?, detail?, toolbar?, detailToolbar?, sheet?})`: the app owns the selected ID and its `select` and `back` parts. Draw list children in `list(activeId, wide)`, including any date headings or custom rows. List and detail slots can contain nested arrays, such as `[heading, rows, footer]`. Omit `list` to show `empty`. The header scrolls with the list. Draw detail from the app's route or its full data, not from the filtered list. With no selection, `detail` is shown beside the list only when wide; pass `defaultId` if that detail corresponds to a row. `detailToolbar` replaces the list toolbar on the folded detail and joins it when wide.
  Omit `detail` for a full-width list.
- `Layout(h, {content, toolbar?, sheet?})`: give the app its own full-size screen instead of the two panes. Use it for an edge-to-edge reader.
- `toolbar: {actions, choose}` takes SF Symbol buttons `{id, label, symbol, disabled?, menu?}`. Menu entries are `{id, label, checked?, disabled?, symbol?}`. IDs are unique per toolbar; `design-sidebar` is reserved. Make `choose` in the screen with `p.part(chooseToolbar(Message.Chosen))`, where `Chosen` takes `{id}`. The same part handles both buttons and menu IDs on both hosts. `detailToolbar` is an array of buttons using the list toolbar's `choose`.
- Either layout can draw a controlled sheet with `sheet: {open, label, dismiss, body, actions?, height?, toolbar?, pending?}`. Supply `dismiss` as a `View.Part<string, [event: string]>`. Its action slots own their messages, and `pending` blocks Escape or swipe dismissal. Height is a fraction of the available screen (0–1). A native sheet is part of the navigation stack.
- `ActionButton(h, {label, press, description?, disabled?, key?})`, `Notice(h, text, retry?)`, `Message(h, text, actions)`, `Headline(h, label, dot?)`, `Caption(h, text)`, `Figures(h, values)`, `Facts(h, {values, extra?})` and `DetailSkeleton(h)` draw the same content on both hosts. `press` is a `Press`: a part with its message arguments given, which each host attaches to its own events (`click`, or `press` and `accessibilityTap`). A screen writes one view over these, generic in the host `H` and its content `C`, and each app's `main.ts` passes its host's drawing; primitives only one app uses stay in that app.
- `styles` and the palette tokens are exported by both renderers. On web, pass `webStyle(styles.row)` to `.style()`; on native pass the object directly.

The Fabric host requires react-native-screens and react-native-safe-area-context to be linked into the iOS target; the JS does not import their React components. Run `vp run --filter @deslop/components preview` for the web gallery. Use `gallery/native/main.ts` as the entry of an Expo simulator build configured with `NativeMetro.withEffectUi` from `@effect/ui-native/node`.
