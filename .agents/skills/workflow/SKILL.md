Next useful evidence, from a real task in a fresh session:

1. The pair executes nothing itself; slices run in parallel.
2. Substantial work shapes an MVP, cut list, acceptance checks, and batched decisions, then executes without check-ins.
3. The first "done" is ready to merge: no user cleanup, reverts, or status prompts.

## Contract

| Message                       | Pair behavior                                                                                                                                                                                                                                                             |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First message                 | Grounding round and discussion before anything is built                                                                                                                                                                                                                   |
| Question or problem           | Assessment with evidence, root cause, recommendation; no changes                                                                                                                                                                                                          |
| Small change request          | Existing-work check, delegated slice, local check, end-to-end acceptance run, ready-to-merge review, commit, push, draft request                                                                                                                                          |
| Substantial work: shaping     | Six-item grounding and discussion; a core prototype before questions when underspecified; MVP is the smallest extension of the nearest feature with cut list and acceptance checks; technical choices stated as recommendations; only product choices asked, in one batch |
| Substantial work: execution   | Autonomous after approval. Disjoint-file slices in parallel, every agent on its configured model, acceptance verified by the pair, no check-ins                                                                                                                           |
| Steer while work is in flight | Answered or queued; in-flight work continues                                                                                                                                                                                                                              |

Standing rules: the pair only coordinates; a ledger carries the user's decisions into every brief and is checked against merges; mechanics happen without asking, decisions are discussed; the engineering skill's Simplicity section bounds scope; checks, lint, and review are fallbacks; done means ready to merge with the thread's artifacts removed; output is schematic.

Harness facts, verified 2026-09-22:

- t3 launches Claude with `--setting-sources=user,project,local` and no system-prompt override.
- A user-level output style reaches the Claude main thread only. A subagent without `omitClaudeMd` receives the repository AGENTS.md; with it, nothing. Roles therefore omit it.
- Claude loads project skills only from `.claude/skills`. `Monitor` is allowed for waits. Deny rules block pushes to main or master and `gh`/`glab` merges by prefix; a bare `git push` with upstream main is not caught.
- Codex roles' developer instructions replace the root's. `[agents] max_depth` is undocumented and was removed; `goals` stays off. Codex role files honor only developer_instructions, model, reasoning effort and summary, verbosity, personality, and service tier; under the V2 agent tools no config stops a spawned role from spawning, so roles state it and the pair enforces it. Running Claude sessions pick up reinstalled agent definitions: a thread's agents switched from Sonnet to Opus after the 10:13 install. Codex command rules live in `~/.codex/rules/`, which the installer would replace, so none ship.
- Models: t3code sets the pair per thread. Implement and review are claude-opus-5-5 high / gpt-6-sol high; general claude-opus-5-5 medium / gpt-6-sol medium; explore claude-opus-5-5 low / gpt-6-sol low; git claude-opus-5-5 low / gpt-6-luna medium; browser claude-opus-5-5 low / gpt-6-luna medium.
- Claude threads reload the pair text when the model or effort changes in the composer (t3code ProviderCommandReactor.ts:757-788) or after 30 idle minutes; Codex needs a new thread. Role files are read at each spawn. ScheduleWakeup (Claude) and Monitor lines wake an idle pair; Codex has no wake.
- Host state (2026-09-24): UFW IPv6 on; shared turbo cache ~/.cache/turbo; `python`, pip into ~/.local, pillow; bc, xxd, sqlite3; acli; agent-browser 0.38.1 global with Chrome; glab default host git.datapizza.tech; library clones in ~/.deslop/repos (shallow, default branch, refreshed before use); /tmp is a RAM tmpfs, scratch goes to ~/.deslop/<task>/; the datapizza VPN allows one device and needs OAuth.

## Package and engineering facts retained

- tools/workflow/src/agents/skills/engineering/SKILL.md is one file of executable good and bad product-code conventions. project-engineering holds repository-specific layout and service rules.
- The workflow package owns its agent assets, installer, shared Oxlint config, ten repository rules, and exported TypeScript config.
- Published TypeScript is built because Node 26 refuses type stripping under node_modules.
- Consumers restate the ignorePatterns and rule options they want; Oxlint merges overrides across extends but replaces those fields.
- A jsPlugins specifier resolves from the linted root. Formatter configuration is duplicated per root because oxfmt has no extends.
- Releases publish @deslop/workflow from main as 0.1.<run number>. The external consumer probe is ~/.deslop/harness-probe/turbo-probe.
